# 游资动向日报 · youzi-radar

每天盘后自动抓取全市场龙虎榜，把几百个营业部席位还原成**有名字的资金主体**（陈小群、作手新一、拉萨天团、开源五鬼……），算出谁在加仓、谁在出货、哪只票被多路资金抱团，然后推送到飞书。

纯 Python + 公开接口，不需要数据库、不需要服务器，GitHub Actions 每天自动跑。

---

## 这份报告有什么

| 模块 | 看什么 |
| --- | --- |
| **资金全景** | 全榜净额，拆成一线游资 / 活跃游资 / 量化 / 外资 / 机构 / 北向 / 散户 |
| **游资加仓榜** | 今天谁买得最凶，买了哪些票（每只票后面带该席位的净买入金额）|
| **抱团合力榜** | 多路游资同时净买入的个股，每个席位后面带它自己那笔金额；买家/卖家家数分开列 |
| **个股净买卖榜** | 个股维度汇总：净买入 TOP10 / 净卖出 TOP10，含买入额、卖出额，以及具体是哪些席位在买卖、各是多少 |
| **游资出货榜** | 谁在撤退，只列净卖出的票，每只后面带该席位在这一笔上的金额（不给席位合计，避免与明细重复计数）|
| **跌停与重挫接货** | 跌超 5%（含跌停）仍被游资逆势买入，博反弹或撬板 |
| **机构游资分歧** | 机构买、游资卖（或反之），典型的换手信号 |
| **连板梯队** | 只统计 2 板以上，每层个股全列；首板数、盘中开板后回封数单列作对照 |
| **量化席位** | 开源五鬼、券商总部这类高频席位单独看 |
| **未收录席位** | 还没被命名的营业部大额买入，往往是新游资 |
| **连续性追踪** | 连续 N 日加仓的席位、连续被买的个股（含今日是谁在买、各买多少） |
| **赚钱效应** | 昨日上榜股今日表现，判断打板环境 |

## 三步部署（全程网页操作，不用命令行）

### 1. 建仓库

把这个目录上传到你自己的 GitHub 仓库（可以是私有仓库）。

### 2. 配置飞书机器人

在飞书群里 → 群设置 → 群机器人 → 添加机器人 → **自定义机器人**：

- 复制得到的 Webhook 地址，形如 `https://open.feishu.cn/open-apis/bot/v2/hook/xxxx`
- 如果安全设置里勾了「签名校验」，同时记下密钥

### 3. 填 Secret 并启用

仓库页面 → **Settings → Secrets and variables → Actions → New repository secret**，添加：

| Name | Value | 必填 |
| --- | --- | --- |
| `FEISHU_WEBHOOK` | 上一步的 Webhook 地址 | 是 |
| `FEISHU_SECRET` | 签名校验密钥 | 否 |

> 想推送到多个群：`FEISHU_WEBHOOK` 里填多个地址，用英文逗号分隔。

然后到 **Actions** 标签页，左侧选「游资动向日报」→ 右侧 **Enable workflow**。

第一次想立刻验证效果：点 **Run workflow**，`date` 留空、`force` 勾上，跑完看群里有没有消息。

默认每个工作日 **19:16（北京时间）** 自动运行。

主触发是 Cloudflare Worker `gh-actions-scheduler` 的准点派发，仓库自带的 cron
只作兜底；两者前后脚各触发一次时，由 `state/push_ledger.json` 按数据日期判重，
第二次只重算报告、不再推卡片。要强制重推，Run workflow 勾 `force`。

> **私有仓库要额外一步**：Worker 的 `GH_TOKEN` 必须勾上本仓库的
> `Actions: Read and write`，否则 19:16 那一档会拿到 404，只能等 GitHub 自己的
> cron（延迟可达数小时）。详见 `BIGApush/cloudflare/worker.js` 顶部说明。
>
> 定时档带了 `--wait-minutes 12`：19:16 龙虎榜若还没披露完，会在作业超时预算内
> 轮询等待，不会因为晚披露而整天没有报告。

## 本地运行

```bash
pip install -r requirements.txt

python -m src.main --dry-run            # 生成报告不推送
python -m src.main --date 2026-11-20    # 指定交易日
python -m src.main --print --dry-run    # 顺便把 Markdown 打到屏幕
python tools/preview.py                 # 控制台速览各项榜单
```

报告写在 `reports/YYYY-MM-DD.md`，历史快照写在 `history/`。

推送前想先设置环境变量：

```bash
export FEISHU_WEBHOOK="https://open.feishu.cn/open-apis/bot/v2/hook/xxxx"
export FEISHU_SECRET="你的签名密钥"        # 没开签名校验就不用设
python -m src.main
```

Windows PowerShell 用 `$env:FEISHU_WEBHOOK="..."`。

## 改席位别名库

**这是整个项目最值得维护的地方。**

打开 `data/youzi_seats.json`，一条规则长这样：

```json
{
  "id": "chentianqun",
  "alias": "陈小群",
  "tier": "top",
  "tags": ["一线游资", "接力", "打板"],
  "orgs": ["银河证券", "中国银河"],
  "match": ["大连黄河路"],
  "note": "近两年高频上榜的一线游资"
}
```

匹配逻辑：

- `orgs`：营业部全名必须包含其中**任意一个**（留空则不限制）
- `match`：还必须包含其中**任意一个**关键词
- **数组顺序即优先级**，先命中的生效

`tier` 决定归类，可选：`top`（一线游资）、`hot`（活跃游资）、`quant`（量化）、`foreign`（外资）、`north`（北向）、`inst`（机构）、`retail`（散户大本营）。

想加新席位，直接往数组里加一条。跑 `python tools/audit_seats.py` 可以列出**当前未收录但金额很大**的席位，这是找新游资最快的办法。

## 数据口径

几个容易踩坑的地方，代码里都处理了：

1. **可转债剔除**。可转债 T+0，成交额和股票不是一个量级，混进榜单会把排名冲垮。
2. **同一股票多个上榜原因去重**。东财同一天会返回「日涨幅偏离 7%」「日换手率 20%」「连续三日累计 20%」等多条，后者是三日累计口径，混用会翻几倍。统一按**单日口径优先**去重。
3. **金额一律由席位明细聚合**，不用个股汇总表的金额字段，保证口径统一。
4. **机构专用席位编码恒为 `0`**，同股多条代表不同机构，用买卖金额作区分键，否则会被误合并。
5. **行业口径统一**用 F10 的 EM2016 二级行业，并累积本地缓存；接口挂了只影响连板梯队的行业标注，不影响金额与排名。
6. **休市日不重复推送**：`--skip-if-stale` 会判断当天有没有新数据。

已知限制：

- 龙虎榜盘后披露，天然滞后一个交易日。
- 只覆盖上榜席位（前五买卖），不是全部成交。
- 席位别名是市场公开流传的俗称，仅用于把同源资金归类，**不代表对任何具体投资者的身份指认**。
- 连续追踪需要历史积累，新仓库刚开始只有 1 天数据，跑满一周后这一节才会出现。

## 常见问题

**群里没收到消息？**
先看 Actions 运行日志。`未配置 FEISHU_WEBHOOK` 说明 Secret 没生效；`飞书返回错误 code=19021` 是签名校验失败，检查 `FEISHU_SECRET`；`code=19024` 是关键词不匹配，去机器人设置里把关键词限制去掉。

**接口抓不到数据？**
东财接口偶尔抖动，脚本自带重试和退避。连续失败时手动 Run workflow 重跑一次即可。

**想改推送时间？**
改 `.github/workflows/youzi-daily.yml` 里的 cron，**同时**改 `BIGApush/cloudflare/worker.js` 的 `PLAN`
（两者漂移时 Worker 正常看不出来，一旦 Worker 失效就会直接漏档）。
注意 **cron 是 UTC 时间**：`16 11 * * 1-5` = 工作日北京时间 19:16。

**报告太长，群里刷屏？**
飞书卡片已经是精简版（约 5KB，接近上限时自动裁掉尾部区块）。完整版在仓库 `reports/` 目录里。

## 目录结构

```
youzi-radar/
├── .github/workflows/youzi-daily.yml   定时任务
├── src/
│   ├── eastmoney.py    数据抓取（龙虎榜、席位、涨停池、行业）
│   ├── seats.py        席位识别
│   ├── analyze.py      分析引擎（聚合、榜单、连续性）
│   ├── render.py       Markdown + 飞书卡片
│   ├── feishu.py       推送（含签名、多群、超限裁切）
│   └── main.py         主流程
├── data/
│   ├── youzi_seats.json      席位别名库（重点维护）
│   └── industry_cache.json   行业缓存（自动累积）
├── history/            每日快照，用于连续性分析
├── reports/            每日 Markdown 报告
└── tools/
    ├── preview.py      控制台速览
    ├── audit_seats.py  查未收录席位
    └── backfill.py     回补历史
```
